**Architecture:** GitHub Rulesets enforce review and the real Actions check. Project CI routes task, release and main-to-develop synchronization PRs; the immutable cooperative OpenHarness remains the task client.

**Tech Stack:** GitHub REST API, gh, Python 3.11+, OpenHarness aebb0c2255a5df275491009285c1a23d03f90771.

1. Audit authentication, all refs, PRs, effective rules, actual check App, pinned tooling and release roadmap. Protect main before other writes; create develop at the checked main commit and apply the same rules.
2. Add contract tests for task-to-develop, denied task-to-main, release provenance and synchronization. Observe failures, then implement routing in `tools/check_gitflow.py` and preserve the existing ownership, size and platform-evidence checks in `tools/check_bootstrap.py`.
3. Change `.harness/config.json`, `.github/workflows/architecture.yml`, `AGENTS.md`, `BACKLOG.md`, `README.md`; document release/hotfix provenance and activation in `docs/architecture/gitflow.md`. Keep the upstream SHA pinned. Keep PR #2 on main.
4. Run contract tests, the project checker and OpenHarness candidate verification. Have another AI session review the candidate; record its actual result against the final head with a COMMENT review. GitHub-account approval is not required. Submit the maintenance PR to main, then synchronize current main to develop and observe actual Actions results.
5. Exercise actual draft PR rejection paths where authorization/evidence is absent. Never fabricate a release or platform PASS. Re-read effective rules and report exact blockers.
