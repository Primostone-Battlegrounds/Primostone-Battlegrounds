# 发布路线与迭代

每个版本以合入 `main` 的范围、运行证据和可回滚产物定义。验收任务合入后由维护者核对完整证据并签发标签。

| 版本 | 迭代目标与任务 | 验收和发布对象 |
| --- | --- | --- |
| `0.0.1` | Gate 0。g0-1 至 g0-7，先导入与运行，再做重放、恢复、四人、性能。 | 六项实测 PASS、独立复核和真实合并证据。内部留存探针及报告。 |
| `0.1.0` | 纯 Lua 核心。m0-1 至 m0-9。共享池、招募、事件、战斗、结算、快照重放。 | m0-9 跑通两席终局。固定初态和命令重跑，状态、事件及快照一致。 |
| `0.2.0` | 1 真人 + 1 AI。m1-1 至 m1-5、m1-12 至 m1-14。两种原创反应、6 个样例随从、招募界面和战斗播放。 | m1-5 完成三局干净导入。录像覆盖选择、招募、两种反应和终局，附 GIL SHA、设备记录和样例资产清单。 |
| `0.3.0` | 单人 MVP。m1-6 至 m1-11、m1-15 至 m1-21。1 真人 + 7 AI、40–50 个原创随从、两个真实领队技能、完整招募、复盘和恢复。 | m1-11 集成。PC 和移动可完成对局、退出和从检查点恢复，目录、素材及批跑证据绑定同一发布提交。 |
| `0.4.0` | 四人私有试玩。m2-1 至 m2-7。协议、房间、座位投影、四人桥接、重连和跨端实测。 | m2-4 集成。三局跨端四人记录、隐私负测、短断线恢复、宿主丢失后的明确终止、帧与输入预算、GIL 候选及回滚演练。 |

正式 `1.0.0` 留给稳定公开契约后的独立计划。候选可用 `0.4.0-rc.1`。每个标签绑定唯一提交，产物 SHA 在发布后固定。

## 兼容与回滚

- 预发布期的次版本承载功能或实验契约变更。补丁只含对该次版本已公布契约兼容的修复。进入 1.x 后，公共契约破坏升主版本、兼容功能升次版本、兼容修复升补丁。
- 规则重放、内容、存档编码和联机负载各自版本化。行为变化更新 `rule_set_id` 或 `content_revision`。历史重放选择原版本，未知格式在写入前拒绝。字段分工见 [产品基线](product-baseline.md)。
- 发布记录含任务 PR 与实际合并 SHA、Git 标签、客户端与编辑器构建、GIL SHA、兼容矩阵、测试证据和回滚演练。

## 按交付推进 Sprint

默认两周。每轮写一个可演示目标，从真实合并依赖满足的任务选最小可验收范围。Sprint Review 展示一个可运行闭环或真实平台实验，独立评审核对证据。回顾调整下轮优先级、阻塞和拆分。 [SemVer 2.0.0](https://semver.org/spec/v2.0.0.html) · [Scrum Guide](https://scrumguides.org/scrum-guide.html)

| 阶段 | 依赖满足后的并行示例 | 合流点 |
| --- | --- | --- |
| Gate 0 | g0-2 合入后，g0-3/4/5/6 无共同独占文件，可分别安排设备和操作者。 | g0-7 等全部六项。 |
| 核心 | m0-1、m0-2；随后 m0-3 与 m0-5 分别解锁招募 m0-4 和战斗 m0-6。 | m0-7 合流，m0-8/9 验证存档与续跑。 |
| 切片 | m1-1/3 规则目录、m1-12 美术、m1-4 AI 各按自身依赖推进。m1-2 后分别推进 m1-13 招募和 m1-14 战斗展示。 | m1-5 集成。 |
| 单人 MVP | m1-5 后分别推进合成、领队、八席配对、反馈、教程、恢复。目录及美术按稳定 ID 分批。 | m1-11 等目录美术、交互、恢复、教学和批跑。 |
| 四人 | m2-1 后并行 m2-5 房间与 m2-7 协议夹具，m2-2/3 打通实机，m2-6 补齐恢复界面。 | m2-4 跨端发布验收。 |

实际开工重新核对目标分支、已合并依赖、所有权及 GitHub 分支和 PR。模块共用契约先合入；新增碰撞通过维护 PR 更新依赖。
