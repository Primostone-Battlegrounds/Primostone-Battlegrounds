# Primostone 规则与接口基线

这里定义首个候选版本的设计值。千星奇域的整数范围、编码、事件容量、定时和恢复能力以 Gate 0 实测为准。发生冲突时，相关任务认领前由维护 PR 修订规则、夹具和依赖。

## 对局与招募

| 场景 | 初始行为和边界 | 负责任务 |
| --- | --- | --- |
| 对局形状 | 核心夹具和垂直切片为两席，单人 MVP 为 1 真人 + 7 AI，联机为 4 真人。战团 7 槽，手牌 8 槽。所有席位选定领队后进入招募。断线时席位保留给原认证玩家。 | m0-1, m0-7, m1-10, m2-1 |
| 经济 | 初始生命 24。每轮重置为 min(4 + 回合号 − 1, 9) 晶砂，首轮编号 1。买价 3，卖出返 1，刷新 1，冻结、换位和上阵免费。商店三档，槽数分别为 3、4、5，升级费用依次 5、7。补给、价格、池份数置于版本化配置。 | m0-3, m0-4 |
| 共享池 | 三档普通随从分别以 12、8、5 份开局。只在可抽档位按剩余份数采样，稳定按目录 ID 排序。买入把商店份额移到手牌，卖出、刷新未冻结槽和淘汰返还原份额。零份生成物不入池。冻结针对整店已有随从，保留一轮并自动解冻。池空留下空槽，已确认的刷新仍扣 1。相应区位满时禁止买入或上阵。 | m0-3, m0-4, m1-6 |
| 命令 | 输出当前座位的合法动作与稳定原因码。排序、购买和上阵引用实例 ID 与目标槽。无效、取消或重复命令保留晶砂、随机游标及状态。结束招募后锁定该席，全体存活席提交才开战。两席版本无倒计时，联机计时以 g0-2 实证为前提。 | m0-4, m0-7, m1-13, m2-1 |
| 战斗 | 战团只在战斗副本中改变。存活随从更多的一方先手，同数用独立战斗随机流。双方交替，攻击者按槽顺序循环。存活且可选的守卫优先进入目标候选，无守卫时用所有存活且可选的单位。成对伤害同时提交，其后处理反应，再批量移除死亡。队列按阶段和事件序号推进；事件预算超限报告失败，取消尚未提交的结算。 | m0-5, m0-6, m0-7, m1-1 |
| 结算 | 平局不扣生命，败方扣 min(8, 2 + 胜方存活随从数)。同轮胜负一起提交，淘汰席只返池一次。多席同时淘汰，按结算前生命降序、再按座位号升序确定名次。24 轮为终局上限，仍存活时按结算后生命降序、再按座位号升序定名次。 | m0-7, m1-10 |
| 配对 | 按座位号升序，先选最低号且上轮未遇的对手，无可用时选最低号。三席以上的奇数场景先给最高号席安排最近淘汰者的公开战团镜像，同轮多名时取排名较高者。无历史镜像则轮空。镜像每轮最多参加一战、不改生命或返池。 | m1-10 |
| 合成 | 按实例 ID 升序选择手牌与战团同目录 ID 的三张普通随从。合成物原地替换参与合成的最左战团槽，否则替换最低手牌槽。继承三张合计的池份额和永久加值，基础攻、生命各加 2。移除临时修正，合成直接结束。 | m1-6 |
| 领队与 AI | 切片先显示两个无技能领队。MVP 增加两个真实技能。主动“校准”每轮一次、花 2 晶砂，让一名己方随从永久 +1 攻；取消不扣费。被动“拾晶”每轮首次确认卖出多返 1。AI 只用该席投影和合法动作，预算用尽就选择合法结束或默认选项。 | m1-4, m1-7, m1-21 |

随从生命损伤、战斗护片和元素印记属于战斗副本。首版由结算回写玩家生命和进度。新增跨战斗永久效果必须登记到规则版本并有独立夹具。

## 元素与目录

| 印记或反应 | 切片规则 |
| --- | --- |
| 棱、潮、鸣 | 每个实例最多一个印记。基础攻击造成正数实际伤害后，按伤害来源的元素附着。无有效组合时以新元素覆盖旧印记，同元素保持单层。 |
| 棱 → 鸣，鸣纹 | 目标已有棱时，鸣消耗其印记。仍存活的伤害来源获得一层战斗护片，抵销下一次受到的 1 点伤害，不叠加。 |
| 潮 → 鸣，涟振 | 目标已有潮时，鸣消耗其印记。对目标同侧相邻两槽中仍存活的单位各造成 1 点伤害。空槽跳过。 |
| 同批顺序 | 主动攻击来源先于反击来源附着。批次中的附加目标以提交基础伤害后的生命为准。反应伤害不附着，因而不会递归触发。事件记录类型、消耗、来源、按槽排序的目标和结果。 |

切片用 6 个原创随从，每种元素两个。棱为岩灯龟 `rock-lamp-turtle`、断层匠 `fault-artisan`，潮为洄溪螺 `eddy-snail`、云汐螈 `mist-newt`，鸣为铜簧蛾 `reed-moth`、回声隼 `echo-kestrel`。样例领队使用 `leader-calibrator` 和 `leader-prospector`，交付切片时显示身份，MVP 接入技能。初始攻击、生命与档位由 m1-3 定稿并纳入测试。客户端用目录 ID 绑定画像，目录首批扩到 22–25 个，最终 40–50 个，覆盖三个档位和三种元素。本路线范围为上述机制、单人及四人私有试玩。

## 权威数据、证据和版本

| 边界 | 交付语义 |
| --- | --- |
| 状态与随机 | 使用稳定座位号、实例号、动作 ID、事件序号。行动抽样与战斗使用独立可注入随机流。快照包含各游标、下一实体序号、共享池、阶段和重复命令的恢复信息。规范编码固定字段和映射顺序，以原始字节和摘要核对。 |
| 可见范围 | 公共字段包含阶段、回合、对局版本、公开生命、淘汰、已结算战果。自己的晶砂、商店、手牌、合法动作及选择只发自己的座位。池余量、种子和完整快照留在权威侧。客户端和 AI 共用投影边界。 |
| 会话与恢复 | 命令含会话标识、动作 ID、预期版本和负载，绑定认证座位。先查重复再比版本。同 ID 同负载返回原确认，异负载拒绝，新合法命令串行提交。权威设备身份不从负载中的座位号推断。拒绝不推进版本。重连只读最新授权投影。恢复窗口、留存和最大负载取 Gate 0 的实测值。 |
| 兼容性 | 发布用 `app_version`。重放固定 `rule_set_id`、`content_revision` 和 `snapshot_schema_version`，联机握手核对 `protocol_version`。已支持版本精确恢复，未知版本在任何写操作前结构化拒绝。 |
| 构建与回滚 | 验收记录提交 SHA、GIL SHA-256、区服、编辑器和客户端构建号、适用设备和已知限制。用对应历史产物和兼容规则回滚。无法恢复的模型版本提供新开局或退出，并留存原证据。 |

外部模拟器提供可裁剪的机械结构对照。原创期望以本文件及后续经审查的项目变更为准。
